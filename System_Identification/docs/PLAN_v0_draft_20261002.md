# Bennett 八关节机器人系统辨识与 Sim-to-Real 对齐计划（v0 草案）

> 状态：`DRAFT / PLANNING_ONLY`。2026-10-02 重新开始，旧的 `System_Identification/` 与根目录 `sysid_*.py` 视为作废（只在需要时回看，不继承结论）。
> 未经用户当次明确授权，不运行任何使能电机/发送运动命令的脚本。

## 1. 目标

让真机与仿真在**相同命令、相同初始条件、相同限制**下产生尽量一致的运动；尽量一次做完整，之后 RL 策略零样本迁移到样机。
范围不只是执行器，凡是能缩小 sim2real 差距的都做：执行器、质量/质心/惯量、传感器、接触、时序。

## 2. 调研结论（决定了方法选择）

| 来源 | 要点 | 对本项目的用法 |
|---|---|---|
| PACE（ETH, arXiv 2509.06342, [代码](https://github.com/leggedrobotics/pace-sim2real)） | 悬空固定基座；chirp 0.1–10 Hz、20–60 s；每关节拟合 电枢惯量 / 粘滞阻尼 / 库伦摩擦 / 位置零偏，加 1 个全局延迟（共 4n+1）；CMA-ES，4096 并行环境；用不同 PD 增益 + 未见轨迹验证 | 全机执行器辨识的主方法 |
| Machines 2026（高减速比四足，Stribeck 扩展） | 在 PACE 框架上加 Stribeck 摩擦；CAD-only 基线与优化后差异很大；辨识比随机化更有效 | 摩擦模型要能升级到 Stribeck |
| arXiv 2608.01697（并联腿） | 阻尼影响低频幅值，惯量影响高频衰减，延迟影响相位；闭链对参数更敏感 | 辨识频段设计 + 闭链处理 |
| Tan 2018 / Hwangbo 2019 | 执行器模型与延迟是 sim2real 两大主因；惯量最不确定 | 优先级排序 |
| 惯性参数辨识文献（Bonnet 2016 等） | 基参数、回归矩阵、物理一致性（伪惯量矩阵正定）、最优激励轨迹 | 质量/质心/惯量工作包 |
| Damiao 驱动文档 | MIT 模式 T = Kp·Δp + Kd·Δv + τff，iq = T/KT；KT/GREF/TMAX 在寄存器里；无公开延迟数据 | KT 必须自己标定，延迟自己测 |

调研盲区（待补）：PACE 官方 Best practices 页没读到；Stribeck 论文全文 403；Damiao 官方手册里的反馈时序。

## 3. 总体策略：自下而上，每关有门槛

先查清约定和时序 → 再单体标定 → 再全机悬空辨识 → 再刚体参数 → 再传感器/接触 → 最后闭环验证。每一阶段用**没参与拟合的数据**考试，过了才进下一关。

## 4. 阶段与任务

### P0 契约与安全（不动电机）
- 导出：关节名/顺序/CAN ID/正方向/零位/限位；策略观测与动作定义、缩放、限幅、频率、Kp/Kd、decimation。
- 真机侧与 Isaac Lab 侧逐项对照，生成一份机器可读的 `contract.yaml` + 人读报告。
- 电机寄存器快照（不使能）：固件版本、KT、GREF、TMAX、PMAX、VMAX、控制模式、超时。
- 安全：反馈超时、位置/速度/转矩/温度阈值、急停独立验证。

### P1 时序与日志（先证明数据可靠）
- 命令与反馈分开记录，单调时钟时间戳、序号、是否新帧、CAN 原始字节。
- 测：真实命令周期、反馈周期、丢帧、重复缓存率、往返延迟分布、USB-CANFD 适配器延迟。
- 母线电压/温度同步记录。
- 干跑（假数据）走通采集→处理→指标。

### P2 单电机台架标定（需台架，见问题）
- KT（电流→转矩）：负载端用力臂+秤或扭矩传感器，线性回归，对比寄存器值。
- 转矩–转速包络：不同电压下的实测，对比厂家曲线。
- 摩擦：低速匀速扫描（正反向，Stribeck 曲线）、静摩擦/粘滑。
- 反驱转矩、背隙、温度对 KT/摩擦的影响。
- 若无台架：降级为全机悬空数据拟合，并在报告里标注该项置信度低。

### P3 全机执行器辨识（悬空，PACE 式）
- 激励：对称 chirp 0.1–?Hz（上限由机械/策略带宽定）+ 阶跃，20–60 s，≥3 次重复。
- 参数：每关节 电枢惯量、粘滞阻尼、库伦（可升级 Stribeck）、位置零偏，全局延迟（先全局，数据支持再分关节）。
- 工具：先试 PACE 官方代码（需核对 Isaac Sim/Lab 版本），不行则自写 CMA-ES + Isaac Lab 重放。
- 验证：换 Kp/Kd、换幅值/相位、随机阶跃；看参数是否撞边界、重复一致性。
- 闭链：仿真里的闭环约束建模方式要先定（见问题）。

### P4 刚体参数（质量/质心/惯量）
- 逐件称重（每个连杆/电机/电池/线缆/板卡），整机称重。
- 质心：悬吊法或多点秤法；惯量：双线摆/扭摆法（机身、典型腿段）。
- 与 CAD/URDF 对比，更新 URDF/USD；闭链机构的惯量要按实际装配状态核对。
- 补充：用悬空数据中的重力/惯性项做回归校验（基参数 + 伪惯量可行性检查）。
- 机身质量与载荷：电池位置、线缆拖拽影响单独记录。

### P5 传感器
- IMU：轴向/安装旋转、陀螺零偏与尺度、加计零偏、噪声谱、数据延迟（可复用旧 `imu_axis_cal.py` 思路，但重写验证）。
- 编码器：噪声、量化、零位重复性。
- 噪声模型参数写入 Isaac Lab 观测噪声。

### P6 接触与足端
- 足端半径/刚度/摩擦系数（不同地面）、恢复系数；落脚冲击。
- 地面材质登记，与仿真摩擦随机化范围对应。

### P7 仿真对齐与闭环验证
- 建立 Bennett 专用 Isaac Lab 配置（`bennett_sysid`），把 P2–P6 结果写入；执行器模型含转矩–转速包络、延迟、摩擦。
- 分级验证：开环重放 → 悬空策略（只看关节轨迹）→ 地面站立 → 慢走 → 目标步态。
- 判据：关节轨迹误差、力矩/电流分布、观测分布对比（真机 vs 仿真）。

### P8 残差处理
- 对不上的部分判断：补实验 / 改模型 / 加随机化（范围由实测不确定度决定）/ 修代码。
- 记录哪些随机化是必要的（做消融）。

## 5. 目录结构（建议）

```
System-ldentification/
├─ PLAN.md                 总计划（本文件）
├─ STATE.md                当前进度、决定、待办（每次会话更新）
├─ docs/
│  ├─ research/            调研笔记与文献摘录
│  ├─ safety_checklist.md
│  └─ glossary.md
├─ config/
│  ├─ contract.yaml        真机/仿真约定（P0 产物）
│  └─ experiment_template.yaml
├─ src/                    公共代码：日志、时钟、IO、指标、绘图
├─ p0_contract/
├─ p1_timing/
├─ p2_motor_bench/
├─ p3_actuator_fit/
├─ p4_rigid_body/
├─ p5_sensors/
├─ p6_contact/
├─ p7_sim_validation/
└─ p8_residual/
   每个阶段内部：README.md  scripts/  data/{raw,processed}/  results/  report.md
```

规则：原始数据只增不改；每次实验有 manifest（硬件、固件、增益、限幅、代码提交、电压）；拟合集与考试集严格分开；真机脚本默认 dry-run，必须显式参数才使能电机。
