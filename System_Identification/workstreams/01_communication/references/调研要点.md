# 调研要点（2026-10-19）

仅供 02 号工作包参考；结论已写入根 `README.md` 的 02 一节。

## Codex 的调研结论（用户转述截图）

- 官方电机例程给出多电机、1 kHz 控制与反馈间隔读取流程，说明应按实际多电机发送负载测试，不能只拿 50 Hz 判断通信负载。
- Device SDK 有时间戳、发送、接收、错误回调，接收回调运行在线程中，官方要求避免耗时操作；文档没有明确时间戳的单位与产生位置。
- Linux `can-utils` 提供记录、序列检查、总线负载统计，面向 SocketCAN，不能直接用于当前 USB SDK。
- 四足 sim-to-real 论文强调控制回路延迟，并用小动作测综合响应延迟，这包含机械响应，与纯通信往返时间不同。
- 收敛为三组：电机通信性能、控制程序实际节拍、IMU 与关节观测时效。

## 我补充的核对

- 部署代码默认 1000 Hz 发令，Codex 指出的负载问题成立；此前"50 Hz，总线不是瓶颈"的判断不成立。
- `libdm_device.so` 是 x86-64，Jetson 不能直接用。
- 反馈新鲜度用的是主机回调时刻，没有用帧自带时间戳。
