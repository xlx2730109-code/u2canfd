背景：我们用 DM-USB2CANFD 双路模块（固件 `dual_app v1.0.0.7`）驱动 8 个 DM-J8006-2EC，上位机 Windows 与 Jetson Orin Nano（aarch64，Ubuntu 22.04，JetPack 6.2），部署用 1 kHz 控制环、每个周期给 8 个电机各发一帧 MIT 命令。现用 1.x 的 `libdm_device.dll`（Python 包 `dmcan_sdk` 1.0.4）。

固件 V2.0.0 与 `libdmcan` 2.1.0 的 arm64 库已在 Gitee 公开，下面只问公开资料里没有说明的。

1. 模块刷成固件 V2.0.0 后，1.x 的 `libdm_device.dll` / `dmcan_sdk` 1.0.4 还能正常收发吗？如果不能，只有在 Windows 和 Jetson 都迁到 2.x 之后才能用吗？
2. 刷写失败或需要回退时，回到 `dual_app v1.0.0.7` 的固件包和流程在哪里？（Gitee `usb2canfd-dual/固件/` 里只看到 V2.0.0。）
3. 1.x 的 `libdm_device.dll` 里有一个 100 ms 的睡眠常量（文件偏移 `0x7F11`，立即数 `0x05F5E100` 纳秒），使反馈每约 110–120 ms 才交给回调一次。这是设计如此，还是已知问题？2.x 是否已经去掉这种批量交付？

5. `libdm_device` 的 aarch64 库里有一个 `heartbeat` 线程（符号 `heartbeat::start`、`heartbeat_thread_func`），出错时向 stderr 打 `heartbeat transfer failed! error LIBUSB_ERROR_TIMEOUT`。它周期性发什么、周期多长、超时多久算失败？USB 心跳超时后设备从总线上消失（`lsusb` 看不到），是固件主动断开还是主机侧的问题？能否关闭或延长超时？1 kHz 连续发令数分钟后偶发（约 13 次会话中 2 次）。
