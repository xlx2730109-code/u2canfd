## 2026-09-17 KP/KD 真实值：现有台阶数据解不开（结论 + 下一步动作设计）

问题：MIT 模式下力矩是电机自己按 `tau = KP·(q_des − q) + KD·(dq_des − dq) + tau_ff` 算的，我们只发 `kp/kd`，不知道电机**实际**用了多少。台阶脚本发的是 `control_mit(m, kp, kd, q_cmd, 0, 0)`，所以 `tau = KP·Δq − KD·dq`，可以直接从反馈反解。

数据：`data/raw/2026-09-17/20260917_002904_step_FL_thigh_a+0.15_r01/`（下发 kp=28, kd=2）。
脚本：`scripts/identify_kp_kd.py`（回归）、`scripts/plot_kp_kd_diag.py`（诊断图）。
汇总：`data/processed/20260917_002904_step_FL_thigh_a+0.15_r01/kp_kd_ident.json`。

**做了三件事，结论是：这一条台阶解不出 KP/KD。**

| 做法 | 结果 | 为什么不能信 |
|---|---|---|
| 全程最小二乘 `tau = KP·Δq + KD·Δdq` | KP=20.48, KD=1.22, R²=0.767 | 快速瞬态里电流环跟不上，力矩滞后 |
| 整体力矩比例 `tau = γ·(kp·Δq + kd·Δdq)` | γ=0.744, R²=0.697 | 同上，γ 是"动态滞后"冒充的缩放 |
| 两个真正稳住的平台（各取末 0.6 s） | KP=27.52 ± 0.11, R²=0.9795 | 稳是稳了，但**只有两个点** |

关键矛盾在两个稳态点本身：

| 稳态点 | Δq | τ | τ/Δq |
|---|---|---|---|
| A（step 末） | +11.91 mrad | +0.2979 N·m | **25.0** |
| B（back 末） | −7.25 mrad | −0.2393 N·m | **33.0** |

一个 Kp 不可能同时给出 25.0 和 33.0。但过这两点的直线斜率恰好是 **28.04**（≈ 下发的 kp=28！），截距 **−0.036 N·m**。也就是说：

> `tau = 28.0·Δq − 0.036`，那个 −0.036 N·m 是一个**固定偏置**——约 3.7 个力矩 LSB，等价于电机内部 ~1.3 mrad 的位置零点偏差，或者一个恒定的摩擦前馈。它加在哪一个稳态点上决定了比值是 25 还是 33。

两个方程解不开三个未知数（KP、KD、偏置），所以 KP 的"真实值"现在只能说：**斜率 28.0，与下发值 28 一致到 0.1%（下发值是被如实执行的）**，但偏置有多大、KD 是多少，这条数据答不了。

另外两条硬约束：
- **KD 完全不可辨识**：两个稳态点的 dq 都是 −0.0110 rad/s，正好是速度量化下限（1 LSB = 90/4095 = 0.02198 rad/s），也就是"静止"。KD 乘以一个恒定的 −0.0110 只会并进那个固定偏置里，跟 KD 本身分不开。
- 数据质量没问题：反馈帧解码与驱动运行时快照比，|Δq| 中位差 0.0000 mrad、最大 0.38 mrad；5665 帧里只剔掉 1 帧非 MIT 布局的寄存器应答帧。

**要让 KP/KD 落地，需要两个新动作（都要电机使能 + 悬空，等你授权）：**

1. **位置台阶梯 ≥4 级**（比如 0 → +4 → +8 → +12 → +16 mrad，每级停稳 1.5 s，再反向走回来）。
   每级停稳后 dq≈0，得到 4~8 个 (Δq, τ) 点。多点拟合一条直线 `τ = KP·Δq + b`：**斜率就是 KP，截距 b 就是那个固定偏置**——两个未知数、四个以上方程，可解。
2. **匀速斜坡 ≥3 个速度、正反两个方向**（比如 ±0.05、±0.1、±0.2 rad/s，每段恒速 2 s，起点终点同一位置）。
   恒速时 Δq 稳定成常数、dq 也稳定成常数，电流环滞后不再影响（所有量都不随时间变），于是 `τ = KP·Δq_ss − KD·dq` 里 Δq_ss 和 dq 都可知，**KD 可以单独解出来**。
   顺带把**摩擦阻尼**一起做掉（这是本工作包的另一半）：同一位置正反两个方向 `τ(+v) − τ(−v) = 2·τ_c`（库仑摩擦），`τ(+v) + τ(−v)` 随 v 的斜率就是粘性阻尼系数。

在这两个动作做完之前，**不要把任何 KP/KD 数字写进仿真配置**。

图：`results/figures/fig3_kp_kd_diag.png` —— (a) 台阶全程（红=力矩，灰带=真正稳住的平台）；(b) τ–Δq 平面：两个稳态星标 vs 指令 kp=28 的理论线（过原点），实线是过两点的拟合线（斜率 28.0），两条线的夹角就是那个固定偏置。

#### KD 的两种估计（都是同一批数据，别混着引用）

8 段高速段的点（每段一个 `KD = KP·ΔΔq / dq_des`）用两种方式汇总：

| 估计方式 | 实验 A（0.05/0.10/0.15） | 实验 B（0.03/0.08/0.13） | 合并 |
|---|---|---|---|
| 逐段算 KD 再平均 | 2.057 ± 0.123 | 2.056 ± 0.109 | — |
| 每批 4 点各自回归斜率 | 2.040 | 2.015 | — |
| 8 点合并回归斜率 | — | — | **2.030**（R²=0.99802） |

三种口径落在 **2.03 ~ 2.06**，两批之间差 1.2%。**写配置时取 KD = 2.05 即可，别写 2.057 也别写 2.030**——那三位有效数字是本方法给不出来的精度。图上标的是合并回归的 2.030。

> 前两行早先记的是 2.058 / 2.057，各高 0.001。原因是当时算这两格用的 KP 不是最终拟合值 28.4094，而 KD 正比于 KP，KP 差一点 KD 就整体平移。**复现时 `--kp` 必须传该关节自己解出的 KP**，别吃 `identify_kd_friction.py` 里 28.41 的默认值——单关节上差 0.001，八个关节里 KP 分散更大时就会差到百分之几。

### 三个方法要点（为什么这样设计才解得开）

1. **KP 靠扫前馈，不靠台阶。** 台阶只有重力负载变，Δq 散布 1~2 mrad，全是噪声。主动扫 tau_ff 0.8 N·m 就把 Δq 拉开了 28 mrad ≈ 70 个编码器 LSB。回归 `tau_rep = KP·Δq + c·tau_ff + b` 三个未知数一次解出。
   - 顺带验出 **c = 1.000 ± 0.008**：反馈力矩里**含**前馈，即上报的 tau 就是实际输出力矩，不用再补偿。
   - 固定偏置 b 在三个位置分别是 −0.0410 / −0.0465 / −0.0462 N·m，确实是**固定**的（不随位置变），实锤了上一节那个 −0.036 的猜测。
   - 对照：不建模 tau_ff、只用 Δq 单变量回归（上一节台阶的做法），KP 出来是 0.79 / −34.1 / 8.80 / −29.2，R² 接近 0 —— 台阶失败的原因就在这。

2. **KD 靠"同速两遍差分"。** 匀速时所有量都不随时间变，电流环滞后失效。
   `dq_des=0`：`tau = KP·Δq₁ − KD·dq`；`dq_des=dq`：`tau = KP·Δq₂`（固件自己把 KD 项抵消）。
   两遍物理负载完全相同 ⇒ `KP·(Δq₁ − Δq₂) = KD·dq_des`。
   **注意分母是 dq_des，不是实测 dq** —— 两边那个 −KD·dq 自己抵消掉了。
   Δq 是 16 位量（1 LSB = 0.381 mrad），比 12 位力矩精细得多，所以这个差分信噪比很高。

3. **摩擦靠"同位置正反两向差分"。** `τ_out(q) − τ_in(q) = 2τ_c + 2b_v·|v|`，重力项在同一 q 上严格相消，**不需要任何重力模型**。

### 踩过的坑（记下来别再踩）

- **Δq 必须用同一行的配对数据算。** `command.csv` 里 `q_cmd_rad` 和 `q_real_rad` 是同一拍记的；早先版本 q_cmd 取命令行、q 取 CAN 帧，两套样本权重不一样（457/443 vs 412/465）。而匀速窗内 Δq 其实还在缓慢漂（实测 1~7 mrad/窗），权重一错配，漂移就被算成假的 ΔΔq —— 同一份数据 KD 从 2.06 散到 1.87±1.12。改成配对后两批实验各自收敛到 2.057 / 2.056。
- **电机自报的 dq 有一个约 −0.016 rad/s 的固定偏置。** 指令 0.03/0.08/0.13 对应自报 0.0091/0.0503/0.1444（注意低速那个偏得最狠），而编码器差分算出来的速度反而略高于指令值。所以**凡是要用速度的地方一律用指令速度**，别用自报 dq。
- **摩擦的可信判据是位置重叠，不是速度范围。** 出/回两趟的实际位置范围差着 `(Δq_out − Δq_in) + 2×0.109 s×v`（后一项是驱动批交付时延 ~109 ms 造成的）。速度越低重叠越小：匀速段 0.9 s 时 v=0.05 只剩 9 个匹配点（直接跳过），加长到 1.8 s 后 v=0.03 有 397 个点。**摩擦实验必须把匀速段拉长**，这就是 r02 存在的理由。
- **`control.close()` 在本机会卡死**（内部 disable_all 能跑完，但进程不退出）。两个实验脚本都在 `finally` 里先显式发 3 次 0xFD 失能，再调 `close()`；跑的时候用 `timeout` 兜底，数据在卡死前已经落盘。

### 摩擦这条数据的成色

实验 B（匀速段 1.8 s）三个点：**0.2108 / 0.2068 / 0.1932 N·m** @ 0.03 / 0.08 / 0.13 rad/s，起伏 8.7%，匹配样本 397/670/698 个/点。
实验 A（匀速段 0.9 s）对照：0.1978 / 0.1810 / 0.2326 N·m，起伏 25%，匹配样本只有 20/195/121 个 —— 噪声大，只作定性对照。

即 **摩擦力矩 ≈ 0.20 N·m，在 0.03~0.15 rad/s 内基本上是个常数**（低速端略高，是爬行/静摩擦的痕迹），**以库仑摩擦为主**。
线性拟合给 b_v = −0.18 ± 0.06 N·m·s/rad：斜率是负的、且只有 1 个自由度，**不要把 b_v 当数用**，只能说"这个速度区间里粘性项分辨不出来，量级小于 0.4"。

### 八个关节批量辨识（`run_all_joints.py`）

上面三个实验在 FL_thigh 上跑通之后，把它复制到全部 8 个关节：

```
py -3.13 run_all_joints.py --dry-run            # 只打印动作序列, 不连硬件
py -3.13 run_all_joints.py --joints 1,2         # 先做两个
py -3.13 run_all_joints.py                      # 全部 8 个, 约 7 分钟
py -3.13 run_all_joints.py --solve-only         # 不测, 只把已有数据重解一遍
```

它自己不碰 CAN，只是个调度器：逐关节依次调 `tau_ff_sweep.py` → `identify_kp_offset.py` → `ramp_velocity.py` → `identify_kd_friction.py --kp <该关节自己的 KP>`。**最后那步必须传本关节解出的 KP**，理由见上面 KD 表下面的注。汇总写 `results/params/all_joints_summary.json`，附每个数出自哪个 run。

**为什么必须逐关节做**：摩擦、装配、预紧每个关节都不一样，共用一组参数没有依据 —— 这份 README 开头写的就是"先做一个关节，流程跑通后再做八个关节悬空"。

安全约定（沿用两个实验脚本原有的逻辑，没放松）：

- 一次只使能**一个**关节，其余电机不下令；全程悬空、不下地；
- 不调用 `set_zero_position`、不发 0xFE，**零位不动**；
- 每个关节各自受 |tau|>3 N·m / 位置越界 / 反馈超时保护；
- 前置检查没过（无反馈 / 位置异常 / 越界）→ 跳过该关节继续下一个，电机没动过，安全；
- **运动中途触发保护 → 立即停整个批次**，交给人看，不自动往下做。

判定"算不算数"只认子脚本自己打的那行 `[+] 结束: <stop_reason>`，不拿关键字猜 —— "保护"两个字在 `--dry-run` 的打印里也有，"结束"在别的脚本里也出现，用关键字匹配会假报警。

**测出来的数只在"悬空、单关节、不下地"这个条件下成立。** 写进仿真配置前先过 10 工作包的新动作验证。
