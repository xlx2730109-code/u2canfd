# DM-J8006 曲线模型审计与使用建议

## 小白结论

这份模型可以继续保留，而且值得做正式对比，但现在不能说它已经“复现了真实电机”。它只回答一个问题：在 24 V 曲线条件下，关节转得越快时最多还能给多少转矩。温度、电池压降、摩擦、背隙、延迟和真实装配差异都还没有放进去。

## 1. 它现在具体表示什么

- 工作点：24 V；
- 坐标：6:1 减速后的关节输出侧；
- 厂家曲线 CSV：15 个负载点；
- 使用 `9–13 N·m` 区间的厂家曲线下降段；
- 用 `20 N·m @ 0 rad/s` 和 `0 N·m @ 190 rpm` 作为说明书锚点；
- 暂时假设正转、反转和正负转矩完全对称；
- 先受常用转矩上限 `effort_limit` 限制，再根据当前速度查曲线，取更小的允许转矩；
- Isaac Lab 版本写在延迟 PD 模型基础上，可以设置延迟几个仿真步。

## 2. 为什么它可能比标准 DCMotor 更接近厂家数据

标准 Isaac Lab `DCMotor` 用一条直线连接零速峰值和空载转速。数字化的厂家曲线不是完全相同的直线，所以在中高转速时，两种模型允许的转矩会不同。

如果真实供电接近 24 V，而且厂家曲线确实适用于我们手上的电机和固件，按曲线查表比只画一条直线更有依据。

## 3. 为什么现在还不能说“更真实”

- 厂家负载图不是完整最大转矩—速度试验；实际下降支只覆盖约 73–119 rpm。
- 0–73 rpm 和约 119–190 rpm 没有对应的完整测量点，代码用直线连接补齐。
- 20 N·m 是短时峰值，当前模型没有峰值持续时间、绕组/MOS 温升和热降额。
- 只表示 24 V；电池电压变化、负载压降、能量回灌和电流限制变化都没有建模。如果仍使用 6S 锂电，真实电压不会一直固定在 24 V。
- 假设四象限对称，没有反向差异和回生区验证。
- 没有减速器摩擦、低速摩擦变化、背隙、结构弹性、有效折算惯量、编码器偏差/分辨率和真实通信延迟。
- 真机反馈转矩的物理含义尚未校准。

## 4. 对当前 8 N·m 训练可能有什么影响

`effort_limit=8 N·m` 会先把转矩压在 8 N·m 以内。低速时厂家曲线允许的转矩高于 8 N·m，所以两种模型几乎一样；速度升高到曲线允许值低于 8 N·m 后，差异才真正出现。

源资料给出的示例中，约 15 rad/s 时：

- 查表得到的上限约 5.89 N·m；
- 线性 DCMotor 约 4.92 N·m。

这说明查表模型在该点反而允许更多转矩，并非一概“更保守”。是否更真实必须用真机高速响应验证。

因此第一步不是马上重训，而是先统计现有策略平时用到了哪些速度和转矩。如果大部分动作都在两种曲线完全相同的区域，换模型对训练几乎不会有实际影响。

## 5. 现有 Trot A/B 并没有测试这份曲线代码

现有 A/B 只修改了标准 `DCMotor` 的三个数字：

- `effort_limit`
- `saturation_effort`
- `velocity_limit`

代码根本没有导入 `DamiaoMotorCfg`，所以 B 组仍是标准直线电机模型，只是使用 `8/20/19.8968` 这组参数，并不是按 CSV 曲线查表。

已有单组确定性输出显示 B 相比 A：

- 基座倾斜 RMS、横向角速度、动作二阶变化和落足冲击更低；
- 前向速度 RMSE 高约 17.5%；
- 接触错配高约 10.3%；
- 平均机械功率基本不变。

有的指标变好、有的变坏，再加上没有真正使用查表模型、没有真机对照、重复训练次数也不够，所以现在不能宣布哪个更好。

## 6. 目前检查到了哪一步

本轮仅做整理和只读诊断：

- 15 行 CSV 的转矩列严格递增；
- `dm8006_envelope.py`、`damiao.py`、绘图工具通过 Python 语法编译检查；
- 复制后逐文件哈希见 `SHA256SUMS.txt`；
- 当前轻量 Python 环境缺少 numpy 和 matplotlib，未重跑数值与绘图回归；
- `--validate-only` 仍然会先加载绘图库，所以在没安装绘图库的轻量环境里也不能运行。

已有源 README 记录的 Isaac Lab 实例化测试和数值结果属于历史声明，本轮没有独立复现。

## 7. 以后怎么做才算公平

1. 统计参考策略平时用到的关节速度和转矩范围，确认是否进入两种曲线真正不同的区域。
2. 给现有 Trot A/B 增加真正的 C 组：使用 `DamiaoMotorCfg`，其他变量完全不变。
3. 在独立任务中确认模型能加载、能运行少量仿真步，并且限矩结果符合预期。
4. 先短时间筛查，再使用相同随机种子做至少 3 组正式对比。
5. 除了 reward，还比较稳定性、跟踪误差、撞限幅比例、落足冲击、速度和功率。
6. 执行器辨识完成后，再给 C 组加入实测有效惯量、摩擦、偏差和延迟。
7. 最终看没有参与调参的新真机轨迹中，`q_real` 和 `q_sim` 哪个模型更接近。

在用户没有明确授权训练或改生产配置前，不执行上述改动。
